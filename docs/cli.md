# Повтор на главной и CLI

Кнопка «Повторить» находится в строке скана на главной, рядом с «Открыть». Создаётся отдельный запуск с прежними целью, профилем, портами, скоростью, исключениями, проектом, частью сети и источником. Старые результаты и ошибки сохраняются. Список обновляется и показывает ссылку на новый запуск; переход в карточку не требуется. Для активных сканов и импортов повтор недоступен. В карточке кнопки нет.

## Запуск CLI

Требуется Python 3, установка пакетов не нужна. Запускайте из папки webscanner. Ключи, вход и файл .env не требуются.

```sh
./webscanner --help
./webscanner projects list
```

Создать проект с частью сети:

```sh
./webscanner projects create "Обследование" --part "Серверная сеть"
```

Одной командой создать недостающие проект/часть и запустить скан:

```sh
./webscanner scan 192.0.2.0/24 --project "Обследование" --part "Серверная сеть" --create-missing --source 192.0.2.10 --profile quick --wait
```

Замените цель и источник на свои. Источник — метаданные точки проверки; он не переключает туннель. Скан выполняется worker сервера WebScanner, а не компьютер, с которого вызвана CLI. Перед повтором проверьте туннель именно в окружении worker. Результаты появляются в прежней общей истории и в проекте; отдельного нового дашборда нет.

Управление:

```sh
./webscanner scans list --project "Обследование"
./webscanner scans status 93
./webscanner scans cancel 93
./webscanner scans retry 93 --wait
./webscanner scans retry 93 --source 192.0.2.20 --profile custom --ports 22,445
./webscanner reports import report.xml --project "Обследование" --part "Серверная сеть" --source 192.0.2.10
```

Другой адрес сервера:

```sh
./webscanner --url http://192.0.2.10:3000 projects list
./webscanner --url http://192.0.2.10:3000 scans retry 93
```

--url и --json — глобальные параметры, указываются перед подкомандой. По умолчанию адрес http://localhost:3000. JSON для скриптов:

```sh
./webscanner --json scans status 93
```

Доступны профили quick, top100, top1000, web, full, custom; для custom нужен --ports. Скорость задаётся --speed normal/fast/hard. Исключения: --exclude-ips, --exclude-hosts, --exclude-ports. --author задаёт автора отчёта, --comment — комментарий. В scan/reports import --project и --part указываются вместе; без них скан/импорт создаётся без проекта. --create-missing явно разрешает создание каталожных записей и не требуется для существующего проекта. Команда projects create предназначена для новой записи: повторное имя вернёт ошибку дубликата.

--wait ждёт завершения; --wait-timeout ограничивает только ожидание CLI (по умолчанию 3600 секунд). Ctrl+C прекращает ожидание, но не отменяет серверный скан. Коды: 0 — успешный ответ/завершение; 1 — failed/cancelled; 2 — ошибка API/параметров/сети; 130 — прекращение ожидания. Автоповтора при ошибке нет: сначала исправьте туннель, затем повторите. Сбой очереди сохраняется как отдельный failed-запуск, его номер возвращается в ошибке.

## Применение обновления

CLI использует API frontend на порту 3000; запуск отдельных сканеров на клиентском компьютере не требуется. Backend и worker должны работать с одной версией кода. Миграция 7 добавляет `retry_of_id` и индекс, сохраняя историю. Она применяется при старте backend; номер 6 не переиспользуется.

Обновление, сохранение базы и файлов описаны в [README](../README.md#обновление-существующей-установки). Перед запуском сканов дождитесь готовности backend и worker. Для отката используйте совместимую копию кода и сохранённые данные своей установки; `scans/` и volume PostgreSQL нужно сохранять вместе.

## Проверки

Python unit-тесты, отдельная API-проверка на SQLite с подменой Celery, JS-проверка кнопки в списке и синтаксис TSX/CSS. API-fixture исполняет функции запуска/повтора из исходника; отсутствующий в среде multipart не требуется. На 18 октября 2026 года Python-тесты, API-проверка и JS-проверка повтора прошли. Работающие PostgreSQL/Redis/Celery и браузер в этом прогоне не проверялись. Новых производственных зависимостей не добавлено.

```sh
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -v
python3 scripts/check_retry_api.py
node frontend/tests/scanTableRetry.cjs
```
