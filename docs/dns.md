# DNS-имена в сканах

## Использование

В форме нового скана настройки находятся в свёрнутом блоке «Имена компьютеров». В нём по умолчанию включена опция «Найти имена компьютеров». Отключите её, если DNS-запросы не нужны. Сервер можно оставить пустым (автоматический выбор) или указать IPv4/IPv6-адрес. Доменные имена серверов не принимаются, чтобы не зависеть от разрешения имени самого DNS.

Режимы транспорта:

- «Авто: UDP → TCP» — сначала UDP, при сетевой ошибке пробуется TCP; усечённые UDP-ответы библиотека также может повторять по TCP.
- «Только TCP» — для окружений, где UDP недоступен.
- «UDP» — обычные запросы начинаются с UDP; для усечённых ответов dnspython может самостоятельно использовать TCP.

Во вкладке «Хосты и сервисы» действие «Имена хостов» находится в строке фильтров рядом с поиском, портами и протоколом. Снаружи виден короткий статус; настройки сервера и транспорта открываются по нажатию и закрываются повторным нажатием, крестиком, Escape или кликом вне меню. Подробности проверки и список DNS-серверов свёрнуты отдельно. Кнопка «Получить имена» запускает фоновую проверку уже сохранённых IP, без сканирования портов. Работает для завершённых, неудачных, отменённых и импортированных отчётов. Пока основной скан активен, ручной запуск недоступен. Результат обновляется автоматически раз в три секунды. Зависшую DNS-задачу можно повторно поставить через пять минут; это не отменяет необходимость проверить worker.

Рядом с IP показываются PTR-имена; раскрытие подписи показывает DNS-сервер, режим запроса, время и попытки. Существующее `hostname` не перезаписывается. Поиск учитывает как исходное имя, так и PTR-имена. DNS-результаты не доказывают актуальность имени или принадлежность устройства домену.

## Автоматический выбор

Кандидаты: сохранённый успешный DNS части сети, до шести IP из текущего отчёта с обнаруженным TCP/UDP 53, до трёх системных серверов из конфигурации worker. Дубликаты удаляются, общий предел — восемь серверов. Если TCP 53 исключён в настройках отчёта, обнаруженные DNS-сервисы не используются как кандидаты. Исключение порта не отключает отдельно указанный, сохранённый или системный DNS.

Кандидаты проверяются PTR-запросами для первых трёх хостов. Приоритет получают серверы, вернувшие имена. NXDOMAIN и ответ без PTR тоже считаются действительными DNS-ответами. Для каждого IP могут проверяться несколько серверов: отсутствие записи на одном не мешает попробовать другой. Указанный вручную сервер используется один, без подмены системным.

Для части сети запоминается только DNS, реально вернувший хотя бы одно имя, из ручных, сохранённых или обнаруженных кандидатов. Системный DNS автоматически не запоминается. Смена сохранённого DNS не меняет старые отчёты. При автоматическом запуске сохранённый режим транспорта используется, если новый режим оставлен «Авто». Для разового скана без части сети настройки не запоминаются.

Автоматический режим может отправлять запросы системному DNS worker. Для проверки исключительно через DNS обследуемой сети укажите его IP вручную. Адрес DNS за пределами сканируемой цели автоматически не обнаружится, если не известен из сохранённых/системных настроек. Сетевой доступ к нему должен существовать из worker.

## Ограничения и состояния

DNS запускается после сохранения результатов Nmap, до httpx. Он проверяет только сохранённые хосты; отдельное обнаружение устройств без открытых портов в активном скане эта функция не добавляет. Nmap по-прежнему работает с `-n`.

Пределы: до 10000 хостов за запуск, 16 параллельных запросов, около 1,2 секунды на попытку, общий бюджет 60 секунд и защитный лимит процесса 70 секунд. Частичные результаты в пределах общего бюджета сохраняются. При превышении числа хостов остальные не проверяются; счётчик отображается в карточке. PTR-запросы поддерживают IPv4/IPv6 в импортированных отчётах, активный скан пока IPv4.

Состояния хоста: `resolved`, `no_record`, `unreachable`, `refused`, `dns_error`, `budget_exceeded`, `no_server`. Состояния задачи: `not_requested`, `queued`, `running`, `completed`, `partial`, `failed`, `cancelled`. `completed` означает окончание проверки, а не получение имени для каждого IP. Неполученное имя не удаляет прежнее `hostname`.

Ошибка DNS не переводит скан портов в `failed`. Отмена основного скана завершает DNS-процесс; удалённый отчёт не создаётся заново поздним результатом. Повторная доставка одной задачи защищена токеном и условным переходом из `queued` в `running`. Параллельный ручной запрос отклоняется.

JSON-экспорт сохраняет исходное имя и отдельные DNS-доказательства; JSON-импорт читает эти доказательства без сетевых запросов. XML/CSV используют PTR как запасное имя, если исходное пустое; подробные доказательства доступны только в JSON. Повтор скана сохраняет параметры DNS, результаты прошлого определения не копируются.

## Применение обновления

Дождитесь завершения сканов и DNS-задач или отмените активные сканы. Перед обновлением сделайте копию PostgreSQL и `scans/`. Пример сохранения базы из корня проекта:

```sh
mkdir -p backups
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > "backups/before-dns-db-$(date +%Y%m%d-%H%M%S).sql"
```

Проверьте успешное завершение команды и наличие дампа. Файловая копия кода ниже не содержит PostgreSQL и `scans/`.

```sh
docker compose up -d --build backend worker frontend
```

В `requirements.txt` добавлен `dnspython==2.7.0`, поэтому одного `restart` для первоначального применения недостаточно. Backend применит миграцию 8 при старте: JSON-поля DNS, статус и токен задачи в `scans`, доказательства в `hosts`, настройки в `network_parts`. Старые данные и таблицы сохраняются. Обновляйте backend и worker вместе; новый скан с включённым DNS содержит дополнительный аргумент, который старый worker отклонит вместо молчаливого пропуска DNS.

Проверка: запустите небольшой скан с известным DNS или откройте старый отчёт, укажите DNS и нажмите «Получить имена». Проверьте имя, сервер-источник и поиск по этому имени. Затем попробуйте недоступный DNS: должен появиться результат «DNS не ответил» без изменения статуса портового скана.

## Откат

Для отката используйте предыдущую версию исходного кода из своей системы контроля версий и совместимые резервные копии PostgreSQL и `scans/`. Дождитесь завершения задач перед заменой backend и worker. Добавленные nullable-поля DNS сохраняются при откате только кода; откат схемы и восстановление базы выполняются отдельно.

Не используйте `docker compose down -v` для обычного обновления или отката кода. Резервные копии конкретной рабочей установки в этот репозиторий не входят.

## Проверки реализации

```sh
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -v
python3 scripts/check_retry_api.py
node frontend/tests/dnsResolution.cjs
```

Тесты DNS используют подменённые ответы и SQLite: проверяют транспорт, отсутствие PTR, отказ/таймаут, лимит времени, сохранение исходных имён, миграцию, повторные задачи, отмену, ошибки очереди, форму и поиск. Обращения к реальному DNS из среды разработки не выполнялись. Сборка Vite/проверка TypeScript и браузерный прогон требуют доступных frontend-зависимостей.
