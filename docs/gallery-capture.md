# Полная галерея WebScanner в тёмной теме

Цель — показать действующие экраны программы: сканирование, карточки, DNS, скриншоты, сравнение и разные режимы карты. Все кадры снимаются с одинаковым размером окна **1600 × 1050**, английским интерфейсом, **тёмной темой** и 24-часовым временем UTC.

В подготовленном исходном пакете ещё нет этих четырнадцати браузерных снимков: среда подготовки не имеет доступа к рабочим контейнерам и не смогла запустить браузерный рендеринг. Скрипт ниже снимает настоящий локальный интерфейс. Иллюстрации и пустые заглушки вместо снимков не добавляются.

## Одна команда для съёмки

Откройте работающий WebScanner на http://127.0.0.1:3000. На Linux с Docker и Python 3 выполните из папки подготовленного проекта:

```sh
bash scripts/capture_gallery.sh
```

Если интерфейс работает по другому адресу:

```sh
GALLERY_URL=http://127.0.0.1:3001 bash scripts/capture_gallery.sh
```

Первый запуск загрузит изолированный браузерный образ Playwright и пакет той же версии. Приложение должно уже работать; скрипт не запускает, не пересоздаёт и не останавливает его контейнеры. Используется host networking Linux для доступа к локальному интерфейсу. Для Docker Desktop требуется поддержка и включение host networking либо адаптация запуска под вашу сеть.

## Что будет снято

| № | Экран |
| --- | --- |
| 01 | Главная: форма сканирования, статистика и история |
| 02 | Карточка скана и фильтры хостов |
| 03 | Карточка хоста: сервисы, баннер, DNS и веб-метаданные |
| 04 | Компактное управление DNS |
| 05 | Галерея скриншотов веб-сервисов |
| 06 | Открытый скриншот сервиса |
| 07 | Сравнение двух отчётов: новые, отсутствующие и изменённые записи |
| 08 | Многоуровневая карта доступности |
| 09 | Окружение хоста: входящие и исходящие наблюдения |
| 10 | «Кто видит сервис»: HTTPS портала из двух источников |
| 11 | Направленная цепочка наблюдений и исходные отчёты |
| 12 | Матрица доступности по источникам |
| 13 | Описание проекта и сохранённая карта |
| 14 | Предпросмотр импорта архива проекта |

Все 14 сцен обязательно проверяются на тёмную тему. Внешний вид приложения берётся из его текущего frontend; фоновые иконки, графы и карточки не рисуются отдельно.

## Демонстрационные данные

Браузер работает в отдельном временном профиле. Его API-запросы перехватываются и получают синтетические ответы из `scripts/gallery/fixtures.json`. Пользовательские проекты не запрашиваются, сканы не запускаются, DNS-запросы не отправляются. Запись в backend запрещена; допускается только перехваченный запрос предпросмотра импорта, который тоже не доходит до сервера.

Для галереи сервисов браузер сначала снимает три вымышленные HTML-страницы. Их изображения используются как демонстрационные результаты веб-съёмки внутри настоящей галереи WebScanner. Это не сайты реальных организаций.

Сравнение и матрица в fixtures получены реальными функциями `compare_reports` и `build_visibility`. Данные используют адреса `192.0.2.0/24` и имена `.example`.

## Результат

После успешной съёмки:

- PNG-файлы сохраняются в `docs/images/gallery/`.
- `contact-sheet-dark.png` показывает всю галерею одним листом.
- `manifest.json` фиксирует сцены, контрольные суммы, тему и отсутствие непредусмотренных API-запросов / ошибок браузера.
- README на русском и английском получают настоящую тёмную карту и галерею основных возможностей.
- `docs/gallery.md` содержит все 14 полноразмерных снимков.
- Рядом с папкой проекта создаётся **`gallery-for-github.zip`**. Его содержимое после распаковки можно загрузить в GitHub за один раз: файлов меньше 100.

При ошибке съёмки README и опубликованная галерея не заменяются. Предыдущая галерея сохраняется в `docs/images/.gallery-previous-*`, а частичные файлы остаются в `docs/images/.gallery-staging-*` для диагностики. Если сценарий перестал соответствовать обновлённым кнопкам или API, он завершается с ошибкой, а не выдаёт неполный набор за готовую галерею.

Образ и версия пакета закреплены вместе, согласно [документации Playwright](https://playwright.dev/docs/docker). В этом пакете используется `1.64.0`.
