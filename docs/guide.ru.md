# WebScanner

[English overview and quick start](../README.md)

Личный каталог сетевых сканов и импортированных отчётов. FastAPI / Celery / PostgreSQL / Redis, React / TypeScript. Активный конвейер: RustScan → Nmap verification → Nmap services → httpx → Gowitness.

## Язык интерфейса

В верхней панели рядом с темой доступен переключатель RU / EN. Русский выбран по умолчанию; язык сохраняется в браузере. В обоих языках время отображается в 24-часовом формате, без AM/PM. Пользовательские данные и результаты сканеров не переводятся. Подробности и поддержка переводов — [docs/languages.md](languages.md).

## SVG и перенос проектов

На странице «Карта сети» добавлены SVG текущего вида и всей карты выбранных отчётов, экспорт/импорт целого проекта в ZIP, описание обследования и сохранение набора отчётов карты. Архив переносит данные, историю и файлы с новыми внутренними ID, без запуска сканирования. Миграция 9 добавляет описание и настройки карты проекта. Перед применением нужна резервная копия PostgreSQL и `scans/`. Порядок применения, ограничения и сценарии — [docs/project-transfer.md](project-transfer.md).

## Повтор скана и CLI

Кнопка «Повторить» доступна прямо в списке сканов на главной. Для работы из терминала используйте `./webscanner --help`: создание проектов, запуск, состояние, отмена, повтор и импорт. Без ключей и отдельного входа. Примеры и применение обновления: [docs/cli.md](cli.md).

## Запуск

```sh
cp .env.example .env
# Укажите собственный POSTGRES_PASSWORD в .env
mkdir -p scans
docker compose up --build -d
```

Интерфейс: http://localhost:3000. API доступен через frontend по `/api` (например, http://localhost:3000/api/scans). Порт backend 8000 на хост не опубликован; Swagger `/docs` через текущий прокси frontend не доступен.
При первом старте создаются таблицы и применяется версионированная миграция старых колонок. Авторизация отсутствует. В подготовленной конфигурации интерфейс привязан к 127.0.0.1; для удалённого доступа требуется отдельное контролируемое окружение.

База хранится в Docker volume `postgres_data`, файлы отчётов и скриншоты — в локальном каталоге `scans/`, подключённом к backend и worker как `/scans`. Наличие файлов в `scans/` не заменяет базу данных. Перед переносом сохраните PostgreSQL и `scans/`. Для независимой установки используйте отдельные COMPOSE_PROJECT_NAME и WEBSCANNER_PORT. Для сохранения существующего Docker volume используйте прежнее имя Compose-проекта. После замены кода перезапустите backend и worker.

## Импорт

Откройте «Отчёты и сравнение» (`/reports`), нажмите «Загрузить отчёты», выберите файл и нажмите «Добавить в список отчётов». Импорт не запускает сканирование. Он создаёт завершённый отчёт в общей истории, сохраняет исходный файл и метаданные импорта в `scans/<id>`.

Поддерживаемые форматы:

- Nmap XML (`nmap -oX report.xml ...`), greppable (`-oG`). XML поддерживает IPv4 и IPv6, имена хостов, ОС, TCP/UDP/SCTP, сервисы и версии.
- Masscan XML (`-oX`), JSON (`-oJ`), list (`-oL`) и строки `Discovered open port ...`.
- FastScan [magisterquis/fastscan](https://github.com/magisterquis/fastscan): текстовый stdout с `SUCCESS IP:порт "баннер"`. Сохранение: `fastscan 192.0.2.10 > fastscan.txt`. Строки INFO/FAIL/ERROR не импортируются как открытые порты. Поддерживаются IPv4/IPv6, баннеры и дубликаты. Результаты для доменных имён требуют сканирования по IP.
- RustScan greppable (`-g`): `10.0.0.1 -> [22,80,443]`.
- JSON/XML экспорт WebScanner; JSON сохраняет веб-метаданные сервисов.
- CSV с колонками `IP` / `IP address` / `host_ip` / `IP-адрес`, необязательными `port`, `protocol`, `service`, `version`, `hostname` / `Имя компьютера`. Разделители: запятая, точка с запятой, табуляция. UTF-8, UTF-16 и Windows-1251. CSV без port сохраняет только хосты.

XML/нестандартные CSV Advanced IP/Port Scanner пока требуют точных названий инструментов и примеров реального экспорта. Универсальная поддержка этих инструментов не заявляется.

Лимит файла 20 МБ, 100000 хостов и 500000 уникальных портов. Дубликаты хостов и портов объединяются. Сохраняются открытые порты; закрытые и filtered не включаются. Пустые, повреждённые и нераспознанные отчёты отклоняются. Разрешён обычный Nmap DOCTYPE без внешних DTD и entities.

## Имена хостов (DNS)

В форме скана включена опция «Найти имена компьютеров». Пустой DNS-сервер означает автоматический выбор: проверяются сохранённый DNS части сети, до шести обнаруженных DNS-сервисов и системные серверы worker. Можно указать IP DNS вручную и выбрать UDP, TCP или автоматический переход UDP → TCP. В ручном режиме системный DNS не подставляется.

После проверки портов выполняются PTR-запросы для найденных хостов. Полученные имена показываются рядом с IP и доступны в поиске. Во вкладке «Хосты и сервисы» есть отдельная кнопка «Получить имена»: работает и для старых/импортированных отчётов, без повторного сканирования портов. Ошибка DNS не меняет успешный статус скана. DNS, вернувший имя и не относящийся к системным кандидатам, запоминается для части сети. Исходные имена отчётов сохраняются отдельно от результатов DNS.

Нужна пересборка backend/worker: добавлен `dnspython==2.7.0`, миграция 8 добавляет только nullable-поля DNS и статус проверки. При обычном запуске через API без `dns_options` и через прежнюю CLI DNS автоматически не запускается. Подробности, ограничения, обновление и проверенный откат — [docs/dns.md](dns.md).

## Поиск в карточке скана

Во вкладке «Хосты и сервисы» доступны поиск по IP (в том числе части адреса), имени хоста, названию сервиса и версии, точный фильтр портов и выбор протокола. Например, `80` в поле «Порты» не совпадает с `8080`. Несколько портов вводятся через запятую и означают любой из указанных; поиск, порты и протокол применяются совместно. Подсказки портов и протоколов берутся из текущего отчёта.

Поиск охватывает весь загруженный скан. На странице отображается до 50 хостов; счётчик показывает число найденных хостов и подходящих портов по всей выборке. Карточки показывают подходящие порты, кнопка «Все порты хоста» раскрывает остальные. Хосты без портов, если они присутствуют в отчёте, доступны при поиске по IP/имени без фильтра портов или протокола.

Фильтры и страница сохраняются в URL (`host_q`, `host_ports`, `host_protocol`, `host_page`), ссылкой можно поделиться или восстановить её после перезагрузки. При изменении условий открывается первая страница. «Сбросить» очищает фильтры и страницу. Фильтрация не изменяет отчёт и полный экспорт. Пагинация уменьшает число карточек в интерфейсе; API по-прежнему загружает отчёт целиком.

Проверка: `node frontend/tests/scanHostFilters.cjs` — сочетания условий, точные порты, протоколы, хосты без портов, ошибки ввода, URL, раскрытие портов и пагинация на 2000 хостах.

## Сравнение

Выберите первый отчёт как базу и второй как сравниваемый. Можно сравнивать два импорта, два скана или импорт со сканом. Доступны завершённые отчёты всей истории, включая другие страницы.

Хосты сопоставляются по IP, порты по `(protocol, port)`. Показываются записи только в первом/втором отчёте, изменения имени, ОС, сервиса, версии и веб-метаданных. Результат можно скачать как JSON.

Отсутствие записи означает только отсутствие в конкретном отчёте: разные цели, наборы портов, таймауты и неполное сканирование не позволяют автоматически утверждать, что хост исчез или порт закрылся. Область импортированных отчётов пока не определяется автоматически.

## Поведение сканирования

- Отмена проверяется между этапами и во время работы процессов; процессы завершаются, статус защищён от перезаписи worker.
- Top1000 использует частотный список TCP из nmap-services, включая порты выше 1000.
- Ошибки и таймауты инструментов завершают задачу с failed. Ошибка XML Nmap не маскируется пустым успешным результатом.
- Проверяются IP/CIDR/домен и порты, ограничена пагинация. Активное сканирование пока IPv4; максимальная сеть — 65536 адресов.
- Удаление завершённых отчётов очищает каталог файлов; активные сначала отменяются.
- История имеет страницы, общая численность берётся из API, остальные счётчики явно относятся к странице.
- Галерея показывает заглушку только при ошибке изображения; metadata скриншотов берутся из Gowitness SQLite.

## Исключения сканирования

В форме раскройте «Исключения — не сканировать». Доступны IPv4/CIDR, имена хостов и TCP-порты/диапазоны. Разделители: запятая, пробел, новая строка или точка с запятой. Максимум 256 адресов/сетей, 100 имён хостов и 10000 исключённых портов. Маски вида *.local не поддерживаются.

Имена хостов разрешаются в IPv4 до запуска сканеров; если DNS не сработал, задача завершается ошибкой. Целевые адреса фиксируются в allowed_targets.txt. Адреса исключаются до RustScan, а порты передаются через --exclude-ports; кандидаты повторно фильтруются перед Nmap. Проверяются пустая цель и полное исключение выбранного профиля. Данные исключений доступны в деталях и JSON/XML-экспорте. Сравнение предупреждает о разных исключениях.

Профиль «Быстрый» включает 31 базовый TCP-порт: FTP 21, SSH 22, DNS 53, Kerberos 88, RPC 135, SMB 445, LDAP 389, смена пароля Kerberos 464, LDAPS 636, Global Catalog 3268/3269, ADWS 9389, WinRM 5985/5986 и другие распространённые сервисы. DNS 53 присутствовал и ранее. UDP и динамические RPC-порты 49152–65535 в этот профиль не входят; для TCP RPC-портов используйте полный или пользовательский профиль.

## Работа с отчётами команды

Раздел «Карта сети» (`/team`):

1. Выберите проект и часть сети в верхней панели, затем нажмите «Загрузить отчёты».
2. Выберите до 50 файлов и для каждого укажите точку сканирования. Автор и время проверки необязательны. Время загрузки не выдаётся за время сканирования.
3. При наличии достоверных параметров укажите общую область целей/портов и подтвердите полноту. Для разных областей используйте разные очереди. Без подтверждения отсутствующие записи означают «Нет данных».
4. Загрузите файлы, откройте список отчётов, выберите нужные и нажмите «Показать доступность».
5. Переключайте таблицу и карту. На карте выберите источник и нажмите устройство для списка сервисов. Можно искать IP/порт/сервис и скачать JSON с источниками.

Старым сканам источник можно назначить в деталях, в блоке «Источник отчёта для командной карты». Не смешивайте разные сети с одинаковой адресацией. Повторные отчёты одной точки остаются отдельными колонками: пользователь сам выбирает период.

Ограничения: до 50 отчётов, не более 50000 записей портов в выбранных отчётах и 5000 уникальных строк матрицы, включая строки присутствия хостов; 100 строк на странице таблицы. Лимита в 80 устройств на карте нет: выбранный источник, свёрнутые ветки и фильтры определяют видимую часть графа. Связи показывают наблюдения сервисов, а не физические кабели или маршруты. UDP-область и автоматическое извлечение полноты скана пока не поддерживаются. Для прерванных сканов отсутствие записей всегда неизвестно. Импорт не атомарен для всей очереди: каждый успешный файл сохраняется, ошибки показаны отдельно, успешные не повторяются при повторном нажатии.

## Общий каталог проектов и частей сети

В верхней панели всех страниц выберите проект и часть сети. Выбор сохраняется при переходах и перезагрузке. Для разовых сканов есть «Без проекта». Если проект выбран, перед запуском скана/импортом нужно выбрать его часть сети.

В интерфейсе создание выполняется кнопками «+ Проект» / «+ Часть сети»; также доступны API каталога и CLI. Названия нормализуются по пробелам и регистру; дубликаты отклоняются. Связи отчётов хранятся по ID, а текстовые имена синхронизируются для совместимости с экспортом.

«Управление» позволяет переименовать проект/часть сети и объединить части одного проекта. Объединение переносит все отчёты и убирает лишнюю часть без удаления файлов. В списке карты сети «Перенести выбранные» переносит отмеченные отчёты в существующие проект/часть сети, с подтверждением. Активные сканы нельзя переносить.

Миграция 5 переносит существующие текстовые группы в каталог. Различия только в пробелах/регистре объединяются; опечатки в буквах автоматически не исправляются. Они остаются отдельными частями для явного переименования или объединения владельцем. Самостоятельные каталожные записи существуют даже без отчётов. При удалении проекта по умолчанию отчёты сохраняются в «Без проекта»; полное удаление доступно отдельным действием.

## Удаление проекта без потери сканов

Основное действие — «Удалить проект, сохранить сканы». Сканы переходят в «Без проекта»: project_id/network_part_id и текстовые названия очищаются, а статусы, результаты, источники, авторы и файлы сохраняются. Части сети и сам проект удаляются.

В меню «Дополнительно» доступно «Удалить проект вместе со сканами и файлами», с отдельным подтверждением количества отчётов. API по умолчанию сохраняет сканы; полное удаление требует delete_reports=true. Старый endpoint удаления проекта также использует безопасное поведение по умолчанию. Активные сканы нужно сначала остановить. Уже удалённые прежней версией результаты это изменение не восстанавливает.

## Карта всего проекта

На странице карты в поле «Просмотр» выберите «Весь проект»: список отчётов и общая таблица/карта охватят все части выбранного проекта. Это фильтр просмотра, он не меняет часть сети для сохранения новых сканов и импорта.

В интерфейсе «Общая адресация» включена по умолчанию и применяется в режиме «Весь проект»: одинаковые IP разных частей объединяются в одно устройство. Для изолированных площадок с повторяющейся адресацией отключите её в «Параметрах адресации» до построения карты. При отключённой общей адресации одинаковые IP разных частей остаются отдельными устройствами. При прямом вызове API параметр `merge_parts` по умолчанию равен `false`; объединение требует `whole_project=true&merge_parts=true`. Подпись части сети у устройства означает группу отчёта, а не автоматически определённое физическое расположение. Источники и части сохраняются в JSON.

Карта: кнопка «Развернуть» открывает просторное рабочее поле поверх страницы (Esc — выход). Начальная высота — 75% окна с границами 480–1000 пикселей; её можно менять вертикальным растягиванием. Доступны масштаб, «Вместить в окно», сброс и перемещение за свободное пространство. Ctrl + колесо меняет масштаб внутри карты. Поиск подсвечивает совпадения, сохраняя соединяющие узлы. Карта поддерживает многоуровневые ветки, окружение хоста и фильтры сервисов; подробнее — [docs/network-map.md](network-map.md).

## Публикация портов

Compose публикует только frontend на 3000/TCP. PostgreSQL 5432, Redis 6379 и backend 8000 доступны внутри scanner-net, без port mapping на хост. Frontend проксирует /api на backend:8000. Backend /docs больше не доступен по localhost:8000. Это не ограничивает доступ к API через frontend и не добавляет авторизацию.

Для применения изменений портов нужен пересозданный контейнер: docker compose up -d --no-build postgres redis backend worker frontend. Обычный restart не меняет port mapping. Не используйте down -v: том базы данных должен сохраниться.

## Профили и лимиты времени

Профили портов: `quick` (31 базовый TCP-порт), `web`, `top100`, `top1000`, `full` (1–65535) и `custom`. Top 100/1000 используют частотный список TCP из `nmap-services`, включая порты выше 1000.

| Скорость | Ожидание соединения RustScan | Размер пачки | Попытки |
| --- | --- | --- | --- |
| `normal` | 5 с | 1000 | 2 |
| `fast` | 3 с | 2000 | 1 |
| `hard` | 2 с | 2500 | 2 |

Общий лимит этапа RustScan — 900 секунд (`RUSTSCAN_TIMEOUT`), каждого вызова Nmap — 600 секунд (`NMAP_TIMEOUT`), httpx — 300 секунд (`HTTX_TIMEOUT`, имя настройки именно такое), Gowitness — 300 секунд (`GOWITNESS_TIMEOUT`). Дополнительная проверка веб-сервисов после httpx ограничена 30 секундами и допускает самоподписанные TLS-сертификаты. Скриншоты также снимаются с допуском недоверенных сертификатов.

Celery ограничивает задачу 3600 секундами (мягкий лимит — 3300). При чтении истории зависшие сканы со статусом `running` старше 3700 секунд переводятся в `failed`. Полнота обнаружения зависит от задержек сети и выбранной скорости.

## Обновление существующей установки

Дождитесь завершения активных сканов или отмените их. Сохраните базу и `scans/`, используйте прежнее имя Compose-проекта для подключения существующего volume. Примените обновление:

```sh
docker compose up --build -d
```

При старте backend создаёт недостающие таблицы и применяет миграции. Миграция 7 добавляет `retry_of_id` и индекс, миграция 8 — поля DNS, последняя миграция 9 — описание и настройки карты проекта; номер 6 зарезервирован прежним экспериментом. Перед запуском новых сканов дождитесь готовности backend и worker.

При изменении только кода в существующих bind mounts достаточно перезапуска соответствующих сервисов; изменения зависимостей или Dockerfile требуют пересборки, изменения Compose — пересоздания контейнеров. Не используйте `docker compose down -v` для обычного обновления: команда удаляет volume базы данных.

## Структура проекта

| Каталог | Назначение |
| --- | --- |
| `backend/app/api/` | API сканов, отчётов и каталога проектов |
| `backend/app/tasks/scan_tasks.py` | Конвейер сканирования Celery |
| `backend/app/reports/` | Парсинг, сравнение, матрица доступности и удаление |
| `backend/app/core/` | Настройки, БД, миграции, процессы и исключения |
| `frontend/src/` | Страницы, компоненты и логика карты React/TypeScript |
| `cli/` | CLI на стандартной библиотеке Python |
| `scans/` | Исходные отчёты, результаты инструментов и скриншоты |

Параметры MinIO и поле `minio_path` сохранены в коде, но текущий Compose не запускает MinIO: скриншоты сохраняются локально и выдаются через API.

## Проверки

Из корня проекта:

```sh
PYTHONPATH=backend python3 -m unittest discover -s backend/tests -v
python3 scripts/check_retry_api.py
(
  for testfile in frontend/tests/*.cjs; do
    node "$testfile" || exit 1
  done
)
```

Python-зависимости перечислены в `backend/requirements.txt`. Для JS-проверок установите объявленные в `frontend/package.json` зависимости:

```sh
cd frontend
npm install
npm test
npm run typecheck
npm run build
```

В исходной среде прошли Python- и JS-проверки. Полная сборка Docker, работа реальных сканеров и визуальная проверка браузера не подтверждены этим прогоном. Подробности — [docs/validation.md](validation.md).
